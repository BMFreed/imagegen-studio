# Project UI: реализация после аудита

Следующий проход по слоям, staging и выбору ресурсов описан в [Project UI polish](./project-ui-polish.md).

Этот проход реализует рекомендации [исходного аудита](./project-ui-audit.md) в
`docs/prototype-app`. Проверяемый объект — текущее рабочее дерево, включая новые
файлы; существующие пользовательские изменения в продуктовых документах сохранены.
Это self-review реализации. Первоначальный аудит и сравнение с InvokeAI описаны
отдельно; тестирования с целевыми пользователями ещё не было.

## Дизайн и границы

Основной пользователь — автор изображения, который перебирает варианты, принимает
удачный результат и возвращается к нему для следующей итерации. Приоритеты экрана:
цель генерации, модель и промпт, изображение, временные результаты, принятые слои.
Пять предметных понятий: Canvas, Smart Patch, принятый результат, версия модели,
переносимые настройки пресета.

Сохраняются фиксированные три панели и plain-text CodeMirror с embedding sidecars.
Из InvokeAI взяты принципы вписывания изображения, явного staging и семантических
сведений о результате. Глобальная bbox-модель, docking и отдельная Gallery не
переносятся. Узнаваемое свойство этого проекта — принятый слой со своими настройками
и принадлежащие Smart Patch варианты.

Палитра сохраняет пять ролей: тёмное поле изображения, нейтральные панели,
контрастный основной текст, зелёное активное/основное действие, предупреждение о
проблемном ресурсе. Убраны светлые кнопки инструментов, свечение рамки изображения
и повторяющиеся `completed` badges. Вместо одинаково заметных карточек, абстрактных
декоративных превью и общих dashboard-метрик приоритет отдан промпту, изображению и
действиям над реальными сущностями проекта.

## Реализовано

- Повторный Generate при открытом staging предлагает Keep results / Discard and
  generate. Отмена задачи сохраняется после её позднего mock callback; соседняя
  задача может завершиться. Новые batch ids не зависят от времени клика.
- Apply показывает вложенные missing resources, называет затронутые секции и
  способ продолжить. Footer находится вне прокрутки. Исключённая секция остаётся
  прежней. Edit original подтверждает потерю временных правок и открывает именно
  выбранный пресет.
- Canvas использует размеры документа и единый scale; Fit учитывает доступную
  область, изменение размера окна и боковых панелей. Zoom и pan сохраняются до
  следующего Fit. Пустой Canvas объясняет следующий шаг.
- Верх настроек показывает Project Canvas / Smart Patch и имя патча. Модель и её
  точная mock-версия доступны до промптов; Canvas Size расположен после них и
  явно относится к документу. Добавлены fixed/random seed, draft-bound VAE и
  precision. Изменение Size через Apply синхронизирует документ и aspect state;
  размер исключается для Smart Patch.
- Предпросмотр и выбор для принятия обозначены отдельно, есть Previous/Next,
  Clear selection и миниатюры вариантов. Opacity, blend и региональные промпты
  меняют session state через Project history. Рендеринг композитора остаётся mock.
- Каждый mock job получает detached generation record до выполнения. Только
  принятие копирует его в Raster Layer или отдельный Smart Patch variant.
  Удаление очереди и последующие правки не меняют baseline принятого результата.
- Контекстное сравнение Generated with / Current Canvas группирует настройки,
  сообщает Same/Changed/Added/Removed/Missing resource/Unavailable. Оно не меняет
  Project. У патча берётся активный вариант; текущая сторона всегда Canvas draft.
  Legacy/error scenario демонстрирует недоступные поля, imported layer — disabled
  No generation data. Mask/bbox/internal resolution не входят в этот diff.
- Create Preset from Result открывает отдельный редактируемый draft. Seed
  исключён по умолчанию; геометрия патча не переносится. Созданный пресет доступен
  в Project Apply и в New Project (для Text to Image) благодаря общему каталогу
  в памяти текущей сессии браузера.
- Home получил более спокойную навигацию и пояснение пустого инспектора; в списке
  пресетов сокращены badges состава, а в Model Manager уменьшено превью, чтобы
  версия и действия находились выше.

## Карта данных и риск

`Generate → frozen queue record → temporary candidate → explicit Add → layer/variant`
— критическая граница PP-005/PP-008. До Add нет нового результата в документе.
При Add создаётся один grouped undo step; undo не восстанавливает staging. Queue
cleanup не владеет данными принятых слоёв. Preset создаёт detached payload без
layer/source/execution context; Apply меняет только выбранные секции активного draft.

Риск provenance трактуется как высокий для инварианта неизменности, хотя здесь
нет production storage. Вариант чтения текущих настроек при Add отвергнут: автор
может поменять промпт, пока очередь ещё выполняется. Принято копирование при enqueue
и повторное отделение accepted record при Add. Для comparison используется Canvas
в соответствии с PP-005, а не удобный, но неверный active-draft helper.

Mock staleness сравнивает draft, bbox, mask revision и internal dimensions с owned
source snapshot активного варианта. Source composite/mask hashes, worker identity,
реальные изображения, global history index и `.igs` здесь не реализованы.

## Проверки

Сценарии и инварианты закреплены в:

- `tests/project-audit.spec.ts`: повторная генерация, поздний callback после Cancel,
  nested-resource warning и восстановление Apply, границы footer и пропорции Fit,
  корректный переход Edit original и доступность нового пресета из Home;
- `tests/project-provenance.spec.ts`: очередь/acceptance/cleanup/undo, текущий Canvas
  против patch draft, исключение patch geometry, независимые варианты, legacy и
  missing состояния, сквозное создание и применение пресета, выбор версии и правка
  промпта после enqueue;
- существующих Project, Prompt, Home, Preset Manager и Model Manager suites.

В изолированной копии `/tmp/igs-provenance-mutation` копирование payload заменялось
на ссылку на живой draft. Тест accepted metadata упал с `frozen positive` против
`later prompt`. После восстановления копирования этот же тест прошёл. Рабочая
реализация при этой проверке не мутировалась.

Первый общий запуск был прерван из-за синтаксиса inline handler после autofix;
обработчик вынесен в функцию. Следующий прогон выявил дублирующую кнопку Models и
селекторы, опиравшиеся на старые wrapper aria-label / название Size. Дубликат удалён;
тесты обращаются к доступному input и Canvas Size. Для CodeMirror под mock clock
вместо DOM fill использовано реальное Ctrl+A / ввод, с проверкой текста до Add.
Проверяемые пользовательские инварианты не ослаблялись.

Финальный результат: **102 tests passed**, typecheck, lint и build успешны.
Браузерный проход по трём разрешениям, comparison и Apply не дал runtime/Vue
errors; отношение сторон проверенного Canvas — 0.75 на всех трёх размерах.
Сборка сохраняет предупреждение Vite о размере общего JS chunk более 500 kB.

Финальные команды: `pnpm run typecheck`, `pnpm run lint`,
`pnpm run prototype:test`, `pnpm run prototype:build`. Снимки Project для
1280×720, 1440×900 и 1920×1080, comparison и раскрытого Apply находятся в
`docs/prototype-app/screenshots/project-ui-pass-*.png` (локальные generated artifacts).

## Что остаётся за этим проходом

Публичные статусы PP-005/PP-006 и других promises не повышены: интерактивный
прототип не доказывает production persistence. Каталог сбрасывается при reload;
генерация и ресурсы симулируются. Не завершены реальная установка/repair ресурсов,
Open in Models с восстановлением отсутствующей зависимости, worker/storage lifecycle,
полный compositor и глобальная история. Тестирование удобства с авторами изображений
остаётся отдельным шагом, а не выводом из зелёного Playwright.
