## Contract and intended result

PP-007/008 and [Generation provenance](../features/project/generate-mode/generation-provenance.md#history-boundary) require one accepted candidate → one accepted result → one history entry. Project history follows current owned document state; Saved generations follows verified explicit Save. Queue rows and staging never define accepted membership.

The next finite slice includes nested accepted Smart Patch variants in both existing histories. Navigation selects/reveals the parent Patch and opens/focuses the exact stored variant in the existing browser. It does not activate the variant, reveal hidden compositing pixels, change camera/settings/seed, create an Undo step, dirty the document or Save. Variant activation remains the separate existing `Select variant` command. Hidden/locked owners remain inspectable. Missing/changed current ownership must preserve unsaved work and explain refusal. Smart Compare/Preset remain outside this slice.

## Identity and navigation choices

The existing `layerId` history field identifies the accepted raster owner: a top-level Raster UUID or a nested variant UUID. The document schema already enforces global uniqueness across the hierarchy. Saved cursor/reference/resource shapes and the SQLite primary key therefore need no migration. Names remain the exact current Raster/variant names; the local list resolves and labels a variant’s current parent from the document. Parent identity is never inferred from a filename or from the originally generated target in provenance.

The current hierarchy is authoritative for navigation. A variant may retain a historical source Patch ID in immutable provenance; moving provenance identity into a new current owner is not a reason to retarget navigation. A dirty revision is allowed if the current accepted owner and exact resource hash still match. History never automatically activates an inactive variant. Parent visibility and lock state do not prevent inspecting its stored history.

Parent-ID image capabilities continue resolving only that Patch’s active contribution. A separate variant-ID capability resolves the exact currently owned immutable variant, including inactive members; it is revision/hash scoped, signed by Main and independently verified before streaming. Saved-image capabilities continue reading only a freshly revalidated saved package. No paths, pixels or current generation settings are admitted from the renderer.
