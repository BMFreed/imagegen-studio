## Why owned copies

The ordinary loader mutates tokenizer vocabulary and encoder tables. Pinned
Transformers resize assigns `old_embeddings.weight.data`, changes table metadata
and updates configuration. Saving the old module pointer or sharing its
Parameter is insufficient; unload is not exact rollback.

Use ephemeral full deepcopies of both warmed native CLIPs and tokenizers under
the existing reservation of the original components. Borrow the original UNet
and, for denoising, VAE. Continue the existing internal encoding operation;
an outer reserving wrapper around the old runner would conflict on those shared
identities. Encoded bindings own their tensors independently; no reusable model
or tensor cache is returned.

The new TI profile admits only pinned native capture hooks and supported native
copy state. Custom closures/copy shadows, preloaded TI/adapters and global
forward or parameter/module/buffer registration hooks refuse before copying or
loading. The existing plain-profile hook policy is unchanged. Capture hooks in
the pinned runtime close over capture key/index and use the current collector;
they do not bind the borrowed original module. Copies are not a sandbox for
arbitrary Python callbacks.

The actual pinned CLIP tokenizer backend contains a native decoder wrapper.
Its deepcopy drops that Python instance attribute and restores its own builtin.
The owner admits only the exact native code/globals and closure containing
`'</w>'` plus that backend's builtin decode, then reapplies the native helper
only to the owned copy. Arbitrary shadows, foreign backend closures and changed
suffixes refuse. Successful native tests independently check the new closure's
ownership; no borrowed wrapper is copied as an arbitrary callback.

Native resize draws random values. Participating TI operations serialize their
`fork_rng` interval and preserve CPU plus the selected CUDA generator state.
Unrelated concurrent global RNG writers, direct forwards and in-place model/
registry mutation remain outside the cooperative contract. No global seed,
precision/device repair, allocator flush or fallback is introduced.

## Preflight and actual loading

1. Detach and validate the complete recipe, resolved references and native
   profiles/ownership; refuse independent resource overrides and unsupported
   effective content before resource work.
2. Bound descriptors, declared serialized bytes and owned-copy arithmetic.
   Read exact no-follow regular-file snapshots using the existing reader.
   Verify size, digest and before/after stat; deserialize only those bytes.
3. Qualify paired `clip_l`/`clip_g` tensors at widths 768/1280, matching counts,
   supported F16/BF16/F32 and finite values. Check both encoder-dtype conversions
   before installing either encoder's vectors.
4. Plan distinct aliases across all effective signed streams. Check both base
   vocabularies and normalized text from every source, including later ordinary
   text and all vector suffixes. Preserve existing longest-first, ASCII-side
   boundary and UTF-16 overlap rules. Snapshot reuse never merges streams.
5. Stage private tokenizers and actual expansion managers. Use the real Compel
   parser/splitter for all pairs/both CLIPs, aggregate emitted rows, coverage,
   pooled membership and native mask budgets before encoder loading/forward.
6. Replay the validated plan into private native copies, verify actual alias
   IDs/vocabulary and **every** loaded row, then use unchanged
   `build_sdxl_conditioning` with internal explicit embedding inputs. Native
   loading never reopens the managed path. Actual true lengths must match
   preflight, including alignment, empty 77 rows and final sign padding.
7. Release private text-component ownership after encoding and consume the
   resulting bindings through the existing native owners. Failure returns no
   partial success; existing scopes/journals release their own state.

Exact consumed snapshots are the guarantee; path/hash metadata does not
authenticate Main catalog ownership. Directory traversal is not OS-atomic.
A replacement after an owned snapshot need not invalidate those already owned
bytes. Main origin, checkpoint identity and transparent-target mode remain
separate caller preconditions.

a leaked global reservation or reusable cache.
