Base `master`, `63c5979`. Contract: [Presets](../features/presets.md), PP-006,

## Prospective boundaries

Medium-risk renderer navigation, reviewed against resource and immutable-source
contracts. Selected-section diagnostics carry exact references from the current
detached Apply payload, including nested positive/negative embedding sidecars.
Resource actions open Model Manager at that category and exact version; display
and readiness remain distinct from library Default and matching nominal IDs.

The logical Apply session remains open while its modal presentation is suspended.
Naive `displayDirective="show"` retains editor DOM/raw values; changing logical
`show` would reset the existing draft watcher and is prohibited on this route.
Wait for the outgoing modal's actual after-leave before opening the next one.
Model Manager close starts the existing guarded catalog read and returns only
after both its actual dismissal and read settlement. Revalidate source/tab/document
ownership after asynchronous steps. A failed/obsolete catalog never silently
repairs a resource or overwrites copied references. Resuming preserves edits,
selection, expansion and invalid raw inputs; only normal explicit Apply mutates
the Project through the existing Main command.

Qualification will use real diagnostics/helpers and existing Apply/storage
neighbors, a causal semantic mutation with green control/restoration, and a built
Electron Project-picker path with actual preload/Main/SQLite. Tiny catalog files
and controlled row withdrawal/restoration prove navigation and exact-file checks,
not trained generation or CivitAI installation. Preserve source preset, Project
history/seed/`.igs` and library policy during navigation; distinguish intentional
library Default actions and restore fixture mutations before cleanup. Inspect
normal/narrow screenshots and keyboard/focus behavior. Heavy runs remain serial,
RAM/deadline bounded and swap-free without new ML runtime/model copies.

The existing PP-006 review pilot is measured on this Project Apply handoff.
Smart Patch remains phase 4; Preset Manager/New Project resource handoffs and
installed-checkpoint Apply→inference qualifications retain their separate owners.

## Review pilot and observed corrections

The PP-006 Apply handoff review pilot is complete for this finite Project route:
real picker baseline RED→GREEN, independent Project/source/library controls,
selected sections and causal semantic mutation are recorded. This does not mark
all Presets or other model-repair contexts complete.

Peer review identified and corrected three reachable cases before qualification:
an invalid source during suspension must not reopen Apply; wrong expected SHA
must not expose another file as selected detail; and ordinary Manager re-entry
must supersede a delayed old return. The first new native attempt exposed focus
loss: catalog-unavailable/missing diagnostic changes replace a button's DOM node.
Stable section/exact-resource action identity now finds the recreated action;
after actual repair removes it, focus falls back to Close Apply Preset.

That attempt also recorded an observer false refusal after physical exit: a
failed service with `MainPID=0` and empty `ControlGroup` was incorrectly treated
as active. The owned controller now accepts failed as a terminal state only
after original PID absence and empty/gone cgroup, preserving all ownership
guards. The attempt is not counted as a successful qualification. Initial
typecheck caught an overly narrow checkpoint-only fixture type; it now uses
the real diagnostic resource union. Lint caught the dataset access spelling in
the focus fix; the final code uses the project-required DOM API.

The second native run passed 14, but its Apply screenshot showed lower edited
fields instead of the new diagnostic actions. The third run explicitly scrolls
the dialog body to its top before viewport capture and checks action geometry.
Root inspected normal/narrow Apply action layouts, missing-version Manager and
wrong-SHA feedback. Header/footer remain visible, text/actions fit and Apply
retains the existing primary hierarchy. **17 source / five bundle hashes**
match the qualified tree/build; original reports retain their actual outcomes.
