# Installed NoobAI author-recipe qualification

## Entry, scope and risk

Authorized roadmap continuation, clean `master` base
`95a5b0876aa96db00598218765d31b61580b8937`. High risk: reuse/update of an
app-owned installed ML worker, exact-file model policy, frozen queue/Retry and
immutable accepted settings. Supporting promises PP-004/005/007/008 retain
their open status. Contracts: managed-model library, generation settings,
provenance, worker protocol and the NoobAI subsection of the roadmap.

The preceding slice implemented worker0.14 and exact ZTSNR/spacing policy,
but qualified native numerics only on CPU fixtures. At entry, the retained shared
runtime/catalog contained worker0.12. Normal application data has no
active runtime; release Install/Repair remain outside this development test.

This slice verifies trained epsilon and v-prediction NoobAI/credited derivatives
through the built production UI and installed non-editable worker. It must not
claim Invoke pixel parity, subjective image quality, complete component matrix,
authored masks/Regional Guidance/Smart Patch, dynamic batches or release readiness.

## Owners and invariants

Model Manager authors independent exact SHA/size prediction and noise policy.
Public Generate captures verified current values; queue freezes the target and
payload; Python applies the native schedule. Temporary completion changes no
saved `.igs`; explicit Add/Save/reopen/comparison retain immutable actual values.
Policy changes before frozen Retry give preserving refusals. Restoring each
field permits the same frozen inputs/target. Original models outside the artifact
root remain unchanged; local catalog preparation is not CivitAI download evidence.

The fixture declares two distinct trained checkpoints, not two interpretations
of a single v-trained file. A wrong epsilon interpretation remains a separate
causal control. The exact creator/version/file, source bytes and recipe revision
are pinned before execution. Parent instructions and derivative instructions are
identified separately; unset profile fields remain assumptions, never inferred
automatically from marker names.

Matched controls change only prediction, zero-SNR, spacing or Euler/Euler a.
Assertions inspect exact durable payloads, actual decoded outputs and independent
native schedule oracles, not just persisted config flags. Genuine Cancel and
restored frozen Retry use the same imported nonzero source. Normal outpaint
requires the existing pinned LaMa file; it does not qualify authored masks.

## Runtime and resource plan

Reuse the existing canonical shared app-data/catalog at its original path;
moving a venv is prohibited. Updating only the worker is allowed only after
physical exit, original installed-file verification, dependency-lock equality,
non-editable wheel construction and a bounded rollback backup. Requalification
must confirm worker0.14, Euler and noise-profile capabilities before activation
metadata references the new installed manifest. Preserve the old provision
report as historical evidence; never rewrite it as a new successful run.

At entry artifact allocation is 12.23 GiB, disk free 64 GiB, available RAM
21 GiB, RTX4080 16 GiB with about 1.1 GiB in use. One additional managed
epsilon checkpoint is approximately 6.94 GB; no second full ML environment is
needed. Confirm actual disk/RAM/VRAM again before trained jobs. Test runs remain
serial, at most 12 GiB RAM, zero swap and a finite deadline; bound the actual
native scope after KDE moves processes, not only the launcher. Bounded 256px,
three-step controls and separately declared author-resolution/step cases have
distinct claims. Operational limits are not model capacity guarantees.

## Checks and failure plan

Strict fixture/readiness guards fail before source copy or inference on unknown
fields, unsupported recipe/modes, old worker, missing capabilities or unbounded
native scopes. Source-attribution validation is not an ML oracle. Healthy trained
matched cases precede semantic mutation; an ignored zero-SNR/spacing/Euler
dispatch must fail a causal assertion, not import/setup/collection. Installed
payload mutations keep exact backups until byte restoration and independent
startup succeeds. Setup failures remain separately reported.

Track run dependencies and protected shared payload in artifact lifecycle files.
Record source/build/installed hashes, exact commands, outcomes, actual physical
exit and cleanup. Further implementation details, source evidence and results
follow after the initial research phase; outstanding questions are resolved from
primary source and code where possible, and asked only for new product decisions.

## Reproduction and test design

The developer entrypoint is `scripts/qualify-installed-generation.mjs`, invoked
with `node --import tsx`, a canonical owned `--fixture` JSON and `--resume` for
the retained compatible runtime/catalog. The strict `noise-profile` fixture
declares all three exact resources and both pinned recipe descriptors before
inference. Available stages are `bounded`, `bounded-lifecycle`, `author` and
`outpaint`; their guards reject unknown/extra fields or inflated completion
claims. Author parameters are explicit per recipe and are not inferred from
the small-control fixture's `side=256` / `steps=3`.

Native runs use separate `systemd-run --user --wait --pipe` units with
`MemoryMax=12G`, `MemorySwapMax=0`, `RuntimeMaxSec=1200`, `LimitCORE=0` and
`NODE_OPTIONS=--max-old-space-size=512`. The harness also bounds and reads back
the actual Electron/worker scope after KDE relocation. This is not merely a
limit on the shell parent. Start the next stage only after the report's native
physical-exit proof and systemd MainPID=0. Guard/build/lint commands use their
own smaller finite units. Exact fixtures, logs and report source hashes are
retained under the evidence root above.

Tests target the used helper/orchestrator or the actual Main downloader; they
do not define substitute generation business logic inside the test. Resource
upgrade tests use real isolated package/report/backup files and controlled
installer/ready collaborators, so their assertions prove filesystem ordering,
preserving refusal and rollback boundaries. Native installed startup and trained
generation remain separate evidence. Source/shape tests are fixture guards,
not evidence of inference correctness. Stage-count validation consumes observed
queue rows and successfully decoded/accepted outputs from the native run.

The existing historical profiles retain their own exact versions and resource
counts; adding worker0.14/noise-profile does not silently relabel earlier
worker0.12 qualification. `pnpm run app:test` includes the three new helper test
files, so these checks participate in the ordinary repository suite.

## Final guard review and verification

Read-only review found two additional assertion/proof gaps, both closed without
changing inference behavior:

- Noise txt2img previously allowed observed totalSteps up to twice the requested
  count. `assertNoiseTxt2ImgProgress` now requires every observed totalSteps to
  equal the frozen steps and completion to reach that step, while allowing event
  coalescing. Bounded/author neighbors and reduced/inconsistent/incomplete/empty
  refusals exercise the used guard. `progress-readback-report.json` independently
  applies it to nine actual stored trained txt2img traces, including both full
  28-step traces. Original reports/statuses/hashes are preserved; this assertion
  strengthening is separately validated and not presented as a new GPU run.
- Upgrade rollback marked `proven=true` after startup, before final filesystem
  equalities. It now requires restored immutable source bytes/modes, dist-info,
  launcher bytes/mode, active pointer, metadata and historical-report bytes first.
  Five independent actual filesystem late-change neighbors retain backup/lock
  and omit the proof flag. A healthy cache-regeneration neighbor allows mutable
  `.pyc` changes after startup: the original complete backup is checked at
  restoration, then the final immutable-source fence excludes Python caches.
  An isolated premature-proof semantic mutation makes the real-filesystem
  regression RED (`true` instead of `undefined`) after healthy restoration.
  Canonical code and installed runtime remain unchanged; both temporary mutant
  files were removed after physical unit exit.
